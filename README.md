# ТИК-Монитор Москвы — интерактивный Telegram-бот

**Два режима:** (1) просмотр 10 последних решений по выбранному административному округу Москвы или ТИК; (2) ежедневная сводка новых решений по выбранным округам/ТИК. В каждом режиме можно выбрать «все решения» или «УИК, ПРГ, назначения, резерв». Поддерживается несколько подписок одновременно.

**Источник:** публичный API сайта МГИК: `/api/v1/tec/list/` и `/api/v1/tec/solutions/`. API и названия полей взяты из проекта предыдущего аудита. Состояние сайта в момент выпуска из этой среды проверить не удалось; после первого запуска обязательно проверьте журнал.

## Безопасность — сначала сделайте это

**Токен, опубликованный в переписке, необходимо отозвать** через Telegram **@BotFather** → `/revoke`, выбрав своего бота. Получите новый токен. **Не присылайте новый токен в чат и не сохраняйте его в исходном коде или репозитории.**

## Быстрый запуск через Docker (компьютер или VPS)

1. Установите Docker + Docker Compose.
2. Скопируйте эту папку на компьютер/сервер.
3. Создайте файл `.env` из `.env.example`. Впишите только что выпущенный **новый** токен в `TELEGRAM_BOT_TOKEN`.
4. Выполните `docker compose up -d --build`.
5. В Telegram откройте своего бота, нажмите **Start** (`/start`). Через `/id` узнайте ID чата. Если хотите сделать бота частным, впишите его в `ALLOWED_CHAT_IDS` в `.env` и перезапустите `docker compose up -d`.
6. Проверьте запуск: `docker compose logs -f tikbot`. Первый обход наполняет базу **без рассылки уже существующих решений**.
7. Для остановки `docker compose down`. База лежит в папке `data/` и не удаляется при перезапуске.

**Важно:** кнопки в Telegram работают в реальном времени **только пока запущен процесс бота**. Если компьютер выключен, уведомления и команды не работают. Для работы 24/7 необходим постоянно включённый компьютер или сервер/VPS/платформа с постоянным процессом. Одного GitHub Actions с ежедневным cron недостаточно для интерактивных кнопок.

## Запуск без Docker

```bash
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
export TELEGRAM_BOT_TOKEN='новый_токен'
export DATA_DIR='./data'
python telegram_bot.py
```

В Windows PowerShell: `.venv\\Scripts\\Activate.ps1`, `$env:TELEGRAM_BOT_TOKEN="..."`.

## Что нажимать в Telegram

- `/start` — главное меню.
- «Последние решения» → округ (**ЦАО, ЗАО, НАО, ТАО и т. д.**), все ТИК или конкретная ТИК → все решения / только УИК и ПРГ → последние 10 опубликованных решений.
- «Ежедневные уведомления» → те же параметры → подписка. Можно создать несколько подписок.
- «Мои подписки» — список и удаление.
- «Обновить решения сейчас» — внеплановое сканирование всех ТИК.
- `/id` — ID личного чата для приватного режима.

По умолчанию обновление реестра — раз в 6 часов, дополнительный обход в 08:50 МСК, ежедневная сводка в **09:15 МСК**. Даже если новых решений нет, приходит краткое сообщение «новых решений нет». Параметры в `.env` позволяют изменить часы. Даты документов берутся с официального сайта и могут отличаться от даты появления на сайте.

## Какие данные и ограничения

- Хранит справочник ТИК, опубликованные решения и подписки в локальной SQLite. Не хранит токен.
- Для решений использует идентификатор API, дату, номер, название и PDF-ссылку, если API её отдаёт.
- Обходит весь каталог ТИК, включая незнакомые ТИК: они доступны в общем списке. Округ определяется по локальному справочнику `regions.py`; **если география новых районов изменится, актуализируйте справочник**. Автоматическое определение округа из API не подтверждено.
- При первом запуске опубликованные решения записываются как исходная база. Новые уведомления — только о решениях, впервые обнаруженных после подписки.
- Учитывает пагинацию решений; сканирует окно **120 дней по дате решения**. Если документ задним числом опубликуют с датой старше 120 дней, он не попадёт в мониторинг. Изменения уже опубликованного решения с прежним ID обновляют карточку, но не вызывают отдельного сообщения.
- Сведения о заседаниях, не опубликованных на сайте, бот не обнаружит. Сайт может временно блокировать автоматические запросы.
- Нагрузка: один обход делает минимум по одному HTTP-запросу на ТИК; соблюдайте разумный интервал.
- У Telegram ограничение скорости отправки: при очень большом количестве решений сводка может растянуться или потребовать повторного запуска.

## Техническая структура

`mgik_api.py` — клиент API, взят из предыдущего мониторинга; `scanner.py` — сканирование; `storage.py` — SQLite; `regions.py` — округа; `telegram_bot.py` — интерфейс Telegram; `compose.yaml` — запуск; `tests/` — автономные проверки без Telegram и без сети.

## Если ничего не присылает

1. `docker compose logs -f tikbot` — найти сетевые ошибки, ограничение доступа или изменение JSON API.
2. «Обновить решения сейчас» — дождаться сообщения о результате.
3. «Последние решения» → «Все ТИК Москвы» — проверить, появилась ли исходная база.
4. «Мои подписки» — проверить фильтр и округ.
5. Помните: первый запуск **не отправляет старый архив**; уведомления появляются после публикации новых решений, а не просто при просмотре исторических материалов.

## GitHub

Workflow `.github/workflows/check.yml` автоматически проверяет код после загрузки в репозиторий. **Это CI, а не постоянно работающий сервер.** Для интерактивного Telegram-бота нужен постоянно работающий процесс. Токен нельзя хранить в репозитории.
